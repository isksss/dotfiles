# プロジェクトの識別

`30_work` の保存先を決めるときだけ参照する。raw の保存や横断検索ではプロジェクトIDの作成を必須にしない。

1. 現在の作業ディレクトリで `git rev-parse --show-toplevel` を実行する。Git 管理外なら現在のディレクトリを使う。それ以外の失敗は報告する。
2. リポジトリURLから `<ホスト>/<所有者・グループ階層>/<リポジトリ名>` をプロジェクトIDとして決める。明示されたURLを優先し、未指定なら `origin` を使う。`origin` がなく remote が1件ならそれを使い、複数あって選べない場合や remote がない・Git 管理外の場合だけ識別先を確認する。ローカルパスからホストや所有者を推測しない。
3. remote URL はサブプロセス出力をメモリ内で受け取り、生の値をツール出力・ログへ表示しない。HTTPS、`ssh://`、SCP形式（`git@host:owner/repo.git`）を同じIDへ正規化する。認証情報・query・fragmentを除き、ホストを小文字化し、末尾の `/` とリポジトリ名の `.git` を取り除く。所有者・リポジトリ名の大小文字とサブグループ階層は保持する。SSHホスト別名、非標準ポート、ローカルURL、未対応形式で識別が曖昧なら確認する。
4. URLのパスは `/` で階層に分割し、各要素に SKILL.md の安全性ルールを適用する。パーセントエンコードされた区切りや `.` / `..` など、危険・曖昧な要素は置換で衝突させず確認する。`https://github.com/isksss/dotfiles.git` と `git@github.com:isksss/dotfiles.git` は、どちらも `30_work/github.com/isksss/dotfiles/<テーマ>.md` に保存する。
5. 同じIDの clone・worktree は同じ保存先を共有し、通常は初回確認を不要とする。対象ディレクトリの `README.md` に正規化済みIDと使用した repo ルート絶対パスを記録する（検索だけなら作成・更新しない）。URL変更や既存の別IDとの統合が必要な場合は確認し、既存メモを自動移動しない。認証情報や生の remote URL は保存しない。
