# 保存・整理

- 保存先が未指定の雑記は `10_raw/YYYYMMDD-HHmmss-<題名>.md`、横断的な知見は `20_note/<テーマ>.md`、プロジェクト固有の記録は `30_work/<プロジェクトID>/<テーマ>.md` へ。プロジェクトIDが必要な場合は [識別規則](project-id.md) を読む。
- Markdown にタイトル、タイムゾーン付き記録日時、出典（元メモへの相対リンクや repo ルート）、本文を記載する。事実・決定・提案・未検証事項を区別し、会話全文やツール出力は丸写ししない。
- 会話の保存では、現在参照できる会話と要約のみから、目的・結果・決定事項・未完了事項・指定された追加メモを日本語でまとめる。他セッションのログを探索せず、参照範囲の限界を明記する。内部の思考過程は保存しない。
- 書き込み時だけ必要なディレクトリを作る。初期化の依頼では4区分を作る。
- 新規ファイルは排他的に作成する（例: Python の `open(path, "x", encoding="utf-8")`）。名前が衝突した場合だけ `-2`、`-3` と連番を付ける。存在確認後の上書き可能な書き込みで代用しない。
- `10_raw` は新規追加のみ。既存ファイルの編集・追記・移動・削除はせず、訂正は元メモへのリンクを付けて新規追加する。整理後も原文を残す。
- `20_note` と `30_work` は対象を先に読み、依頼範囲の最小差分で更新する。整理では元メモへの相対リンクを残す。
- 不要な note / work は削除せず `99_archive/YYYYMMDD-HHmmss/<元の相対パス>` へ。対象と影響（参照リンクを含む）を示して確認し、承認された対象だけを移動する。元の階層を保持し、既存ファイルは上書きしない。
- 既存の `data.local` や `~/memo` は自動移行しない。移行は明示依頼時に対象と方式を確認し、raw はコピーによる新規追加だけとする。`data.local` の移動・削除は禁止。
- 保存・更新後は内容を読み返し、移動後は移動先と元パスを確認する。結果・絶対パス・未検証事項を報告し、失敗を成功扱いにしない。
