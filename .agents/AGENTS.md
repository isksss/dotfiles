# Global AGENTS.md

- 日本語で簡潔に回答する。
- 秘密情報や認証情報を出力・記録しない。
- 実装を左右する不明点だけを確認する。選択肢は可能な限り数字だけで回答できる形式にする。

## 変更と完了の基準

- 依頼された結果を、既存の構造に沿った最小限の変更で実現する。要求外のリファクタ、将来向けの抽象化、依存追加をしない。
- 対象、期待する結果、確認方法を依頼と関連ファイルから定める。文書や skill は作業に必要なものだけ参照し、固定の工程や skill の連続呼び出しは必須にしない。
- 依頼範囲内の局所的な判断は進め、変更に見合う検証と変更起因の失敗の修正まで行う。各工程で再承認を求めない。
- 検証とドキュメントは変更のリスクに比例させる。完了時は変更内容、検証結果、未検証事項を簡潔に報告する。

## 判断の境界

- 編集前に Git 状態と対象を確認し、既存差分や未追跡ファイルを保持する。
- 目的、外部仕様、公開範囲を変える判断や、削除・履歴の書き換え・既存作業の破棄などの破壊的な操作は、対象と影響を示して確認する。
- branch 作成、commit、push、PR/MR 作成はユーザーが明示的に依頼した場合だけ行う。
