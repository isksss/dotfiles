# Global AGENTS.md

- 日本語で簡潔に回答する。
- 秘密情報や認証情報を出力しない。
- ユーザーへ選択肢で質問するときは、可能な限り数字だけで回答できる形式にする。

## シンプルさ

- 依頼を満たす最小限の変更を優先する。
- 現在の要件に不要な抽象化、汎用化、設定項目、依存関係、ファイル分割を追加しない。
- 将来の拡張を推測して設計せず、確認できる現在の要件だけを実装する。
- 既存の構造と実装を再利用し、要求外のリファクタ、最適化、追加機能を含めない。
- テストとドキュメントは変更内容とリスクに比例させ、新しい仕組みの導入自体を目的にしない。
- 回帰テストは自動的に追加しない。同じ不具合の再発可能性があり、既存テストでは検知できない場合に限り、原因となった挙動を直接検証する最小ケースを追加する。
- 依頼範囲を広げる複雑さが不可欠な場合は、理由と最小案を示して実装前にユーザーへ確認する。

## 開発フロー

- 変更は原則 `plan → implement → test → review` の順で進める。小さな変更も各工程を簡略化して適用する。
- 要件や事実に不明点がある場合は、必要に応じて `grilling` または `research` を先に使い、結果を `plan` に渡す。
- `plan` は対象、変更内容、検証方法、リスクを決める。`implement` は計画の範囲だけを編集する。
- `test` は検証コマンドを実行し、`review` はテスト結果と差分を読み取り専用で評価する。
- test の失敗は `implement → test`、review の指摘は `implement → test → review` に戻る。計画変更が必要なら `plan` に戻す。
- branch、commit、PR/MR はユーザーが明示的に依頼した場合だけ実行する。
